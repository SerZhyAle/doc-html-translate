# OCR sweep over the local corpus, 2026-08-13

Feeds [`DEV/plan/2026-08-13_ocr-sweep-plate-composition.md`](../plan/2026-08-13_ocr-sweep-plate-composition.md).

## Method

Build `26.0813.0245` (`build/doc-html-translate.exe`), engine
`C:\Program Files\Tesseract-OCR\tesseract.exe`, `eng` data. 21 inputs from `test_doc/` chosen to span
the OCR-relevant classes: balloon scans, dense prose scans, a poster, a broadside, blackletter, seven
image containers of one identical page, a UI screenshot, real-world document scans, a comic archive,
an illustrated EPUB, and the non-ASCII-path repro.

Each case ran into its own folder, so no output was reused:

```
doc-html-translate.exe -notranslate -noopen -force -ocr -ocr-lang eng -folder temp/ocrsweep/<case> <input>
```

Then every `index.html` was rendered in headless Edge at 1280x1800 with a 6 s virtual-time budget and
**read as an image**, not parsed. Plate geometry was recomputed from the emitted inline styles
(`width` x `min-height`, both in percent of natural image size), which is the same percentage pair
the renderer positions with.

Scripts, logs, outputs and screenshots: `temp/ocrsweep/` (gitignored) - `run.ps1`, `shots.ps1`,
`stats2.ps1`, `<case>.log`, `_shots/<case>__index.png`.

## Result: every run passed every automatic check

All 21 exited 0. All 21 logs end in `Done.`. `scripts/verify-html.ps1` returned `broken=0` for every
case whose index it could resolve. **The defects below are invisible to all of it** - they were found
only by looking at the rendered pages.

## The four defects

### 1. Region merging (dominant)

- **03 poster**: twelve creed lines -> one plate, 43.9% wide x 70.4% tall, positioned over the middle
  of the source text. Lines above and below it remain uncovered, so both layers are legible at once.
  Its second plate reads `+k] ARMY VALUES` for `ARMY VALUES`.
- **02 cover**: a plate whose text is the foot-of-page fine print
  (`el ADVENTURES ON OTHER\WORLDS-THE UNIVERSE (OF THE FUTURE`) renders **over the `PLANET COMICS`
  logo** at the top of the page.
- **14 `accounts.jpg`**: a single plate covering 80.6% of the image, its 268 characters set large
  enough to fill the box. The source screenshot is no longer visible. Log says `1 image(s) overlaid`.

### 2. Plates do not conceal

`.ocr-box{background:transparent}`; the opaque colour is on the inner `.ocr-ink` span, which wraps
the text run rather than the box. Wherever the recognized string is shorter than the source region -
every merged plate - the source lettering shows around it. Clearest on 04 (17 plates, none oversized,
both layers readable) and 15 (a contract scan where recognized clauses sit beside the printed ones).

### 3. Language never follows the document

13 `image.png` is a Russian UI screenshot. Under `eng` it yields transliterated debris -
`Katanoru-nonyyarenn | Npocmorp | Bugeo u Kavecteo`, `HaxkmuTe «Hayatb»`, `y 26.7.11.0041` - laid over
a readable interface. Output strictly worse than input.

### 4. Honesty

- 06 `NASA-Quaoar`: no raster is extracted, and the fallback page states *"OCR is disabled, so the
  original PDF is shown as-is."* The run had `-ocr`. The sentence is a literal in
  [`internal/pdf/extract.go:1323`](../../internal/pdf/extract.go), not a reading of the flag.
- All cases: in single-page mode plates are written to `index.html` only. `page_001.html` is the bare
  `<img>` with no overlay and no pointer to one - verified on 03 (766 bytes, zero `ocr-` markers).

## Two findings outside the overlay

**05 blackletter extracts a corrupt raster.** `pdf_images/..._1_Im001.jpg` (4363x6193, 595 877 bytes)
is a pink/brown smear with the text drawn into vertical streaks. Converting the same PDF **without**
`-ocr` produces a byte-identical file (sha256 `DB678B4BF7B74B86..`), so the corruption is in
`internal/pdf` raster extraction and precedes OCR. The log then reports
*"nothing matched the eng (English) data"*, which points the user at the language pack for a defect
that has nothing to do with language.

**`scripts/verify-html.ps1` false-FAILs EPUB output.** For 19 the root `index.html` is a 142-byte
redirect to `OEBPS/index.html`; the script checks the redirect and resolves its 55 image references
against the wrong directory, printing `broken=55`. Pointed at `OEBPS/`: `total=55 render=55 broken=0`.
The check cannot currently gate an EPUB conversion.

## What this does not measure

No ground truth was used - transcripts were read by eye against the source images, so word-level
recall and IoU are not reported here; that is the lab's job
([`tools/ocrlab`](../../tools/ocrlab/README.md)) and these scenes should enter its corpus first. The
sweep also ran `eng` only, single-page mode only, and on one machine's Tesseract install (the system
one at `C:\Program Files\Tesseract-OCR`, not the bundled `build/tessdata`).
