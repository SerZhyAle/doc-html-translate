# doc-html-translate - конкурентный ресерч и роадмап функционала

> Параллельное исследование аналогичного софта в интернете: какой функционал ещё можно реализовать.
> Метод: 6 параллельных веб-обзоров по непересекающимся категориям аналогов -> извлечение фич -> дедупликация и приоритизация -> адверсариальная веб-проверка топовых фич -> критика полноты.
> Объём: 45 агентов, ~1.93M токенов, 598 веб-вызовов. Просканировано **54 инструмента-аналога**, сгенерировано **69** кандидатов, после дедупликации - **36 фич** роадмапа, из них **31 верифицирована** по первоисточникам (все подтверждены как реально существующие у названных конкурентов и реализуемые в Go). Плюс критик добавил **11 фич** и **7 категорий**, которые не были покрыты.

---

## 1. Что приложение уже умеет (базовая линия, не предлагать заново)

Конвертация EPUB, PDF, MOBI, AZW3, FB2, RTF, TXT, Markdown, HTML в чистый самодостаточный локальный HTML; генерация навигации и оглавления; автоперевод через Google Cloud Translation API (ключ пользователя) или локальный Ollama; бесплатный перевод страницы средствами браузера; мгновенное повторное открытие (кэш); открытие файлов из Проводника через ассоциации; десктоп-GUI на Go + CLI; поставка через Microsoft Store (full-trust MSIX). MOBI/AZW3 требуют установленного Calibre.

## 3. Детальный роадмап по группам

Для каждой фичи: суть -> текущий пробел -> где видели у конкурентов -> результат адверсариальной проверки (важные инженерные оговорки сохранены, поскольку они меняют объём работ).

### 3.1 Точность конвертации

**[1] Импорт настоящего оглавления + многоуровневый TOC с якорями** _(Высокий / Средние)_
Заменить плоский TOC по порядку spine (одна запись на файл, подпись - имя файла или первое предложение) на настоящее многоуровневое оглавление: парсить авторскую навигацию EPUB (EPUB2 `toc.ncx` navMap, EPUB3 `nav.xhtml`) и PDF outline/bookmarks; для PDF/TXT/MD/FB2 - фолбэк сканированием заголовков h1-h6 со стабильными `id`-якорями. Эмитить вложенные `<ul>/<details>` с глубокими ссылками (`page_003.html#sec-2`), флаг `-toc-depth N`.
- Пробел: `htmlgen.GenerateIndexWithSnippets` строит TOC только из порядка spine; `toc.ncx`/`nav.xhtml` находятся, но игнорируются (`epub.parseOPF` читает только manifest+spine+title).
- Видели: Calibre, Sigil, EbookLib, Pandoc (`--toc-depth`).
- Проверка (high): PDF-bookmarks бесплатны - уже вендоренный `ledongthuc/pdf` даёт `Outline()` с вложенным деревом, а `pdfcpu` - `Bookmark{Title,PageFrom,Kids,..}`. Поправки: убрать из списка pdf2htmlEX/Okular/WeasyPrint (они либо вьюверы, либо генерят bookmarks в обратную сторону); самая трудоёмкая часть, которую ни одна библиотека не даёт - инъекция стабильных `id`-якорей и ремаппинг NCX-фрагментов на переименованные файлы после `xhtml->html` нормализации.

**[2] Пасс нормализации текста** _(Высокий / Средние)_
Общий `textutil`-пасс перед генерацией HTML: разворачивать жёсткие переносы внутри абзаца, склеивать дефис-переносы, повышать неразмеченные заголовки (ALL-CAPS / "Chapter N") до `<h2>`, схлопывать пустые строки в разделители сцен, детектить повторяющиеся по позиции строки (колонтитулы, номера страниц) и удалять их.
- Пробел: логика разрознена и только для PDF (`classifyBlock`, `parsePDFLayoutPage`); TXT/RTF/MD получают минимум структуры, колонтитулы протекают в каждую страницу.
- Видели: Calibre (почти 1:1 - `Dehyphenator`, `punctuation_unwrap`, `markup_chapters`, `detect_soft_breaks`), Marker, MinerU.
- Проверка (high): Pandoc и Sigil из списка убрать (нет де-дефиса/детекта колонтитулов). Срез колонтитулов работает только там, где сохранены границы страниц (PDF c `\f`); для TXT/EPUB это no-op. Риск: эвристики лоссовые (ломают стихи, код, таблицы) - делать off-by-default с пер-пассовыми тумблерами, как в Calibre.

**[25] Восстановление порядка чтения в многоколоночных PDF** _(Средний / Средние)_
Детектить 2-колоночную вёрстку и пере-сшивать текст в правильный человеческий порядок (левая колонка целиком, затем правая).
- Пробел: многоколоночные PDF читаются построчно поперёк колонок, текст перемешан.
- Видели: MinerU, Adobe PDF Extract, Mathpix, LlamaParse.
- Проверка (подтв. **с важной поправкой**): предложение "переиспользовать `rowsToText` firstX/y" ошибочно. (а) Основной путь - внешний `pdftotext`, а Go-fallback с `rowsToText` запускается редко. (б) Даже в fallback `GetTextByRow()` мерджит строку левой и правой колонки по общему Y _до_ `rowsToText` - информация уже потеряна. Правильный подход: работать с сырым потоком глифов (X,Y,W), гистограмма по X для поиска жёлоба, бины колонок. Для основного пути - флаги `-layout` у `pdftotext`. Чистая эвристика хрупка против ML-моделей конкурентов; риск регресса одноколоночных книг.

**[26] Распознавание таблиц -> HTML `<table>`** _(Средний / Высокие)_
Эмитить настоящие `<table>/<tr>/<td>` вместо плоских абзацев; ячейки помечать переводимыми сегментами.
- Видели: Docling (TableFormer), Marker, MinerU, Adobe, LlamaParse, Mathpix.
- Проверка (подтв. **с поправкой**): все высокоточные конкуренты используют обученные ML-модели, а не whitespace-эвристику - так что PDF-путь через `pdftotext -layout` будет низкой точности. Премиса "для DOCX/XLSX таблицы явные" ложна - таких входов в коде нет. Самый ценный низкорисковый срез: сохранять/сегментировать уже существующую `<table>`-разметку из HTML и EPUB/XHTML входов (тривиально и надёжно).

**[31] FB2: встроенные картинки и инлайн-форматирование** _(Средний / Средние)_
Декодировать `<binary id>` base64-блоки, писать как `<img>` в точках `<image>`; сохранять `<emphasis>/<strong>`; использовать встроенную обложку.
- Пробел: FB2-парсер берёт только `<p>`, картинки и форматирование выбрасываются.
- Видели: FBReader, Calibre (`fb2_input.py`: `extract_embedded_content`).
- Проверка (high): извлечение картинок и обложки - механика на stdlib (`encoding/base64`). **Важная оговорка**: `xml.Unmarshal` в структуры теряет порядок и смешанное содержимое - точки вставки картинок и инлайн `<emphasis>` нельзя восстановить тегами структур, нужен переход на потоковый `xml.Decoder` (или `,innerxml`). Это переписывание парсера, а не маленький патч.

**[34] Сохранение формул (MathML / LaTeX)** _(Низкий / Высокие)_
Детектить уравнения и эмитить MathML (нативно в браузерах) либо LaTeX в делимитированном span; защищать математику от перевода (как `<code>/<pre>`).
- Видели: Marker, MinerU, Mathpix, Docling. _(Не верифицировалось отдельно - низкий приоритет.)_

### 3.2 Форматы на вход

**[3] Вход DOCX/PPTX/XLSX/ODT с маппингом стилей** _(Высокий / Средние)_
Office-форматы в `pipeline.go`. DOCX/PPTX/XLSX - это ZIP+XML, парсятся чистым Go (`archive/zip`+`encoding/xml`) как существующие `epub`/`fb2`; ODT/сложные - опционально через LibreOffice headless. Читать именованные стили (Word "Heading 1" -> `h1`), слайды -> страницы, листы -> HTML-таблицы; эмитить `*epub.Book`.
- Видели: mammoth.js (точный аналог "читать стили, не угадывать"), LibreOffice headless, MarkItDown, Pandoc, Calibre.
- Проверка (high): архитектура уже точно под это (ZIP+XML -> `*epub.Book` через format switch). **Оговорки**: "Heading 1 -> h1" требует разрешения indirection - `<w:pStyle w:val="Heading1"/>` в document.xml, а человекочитаемое имя в styles.xml (через `w:basedOn`); зрелого pure-Go аналога mammoth нет (писать маппинг самим); LibreOffice тяжёлый (сотни МБ, грязный HTML) - держать только для ODT/краёв.

**[4] OCR для сканированных/image-only PDF и картинок** _(Высокий / Высокие)_
Когда текстового слоя нет (код это уже детектит и сейчас встраивает сырой PDF в `<embed>`), за флагом `-ocr`: рендерить страницы в растр, прогонять через Tesseract (детект на PATH, winget-автоустановка как Poppler/ffmpeg) или Ollama vision, эмитить `<p>` в общий пайплайн. Добавить `.png/.jpg/.tiff` как входы.
- Видели: MarkItDown (`markitdown-ocr` - почти точный механизм: рендер 300 DPI -> LLM-картинка), MinerU (PP-OCR, 109 языков), Marker (Surya).
- Проверка (high): **критичная поправка** - `extractImages` НЕ даёт растры страниц, а вытаскивает встроенные image-XObject (`pdfcpu ExtractImagesFile`); нужен настоящий рендер страницы (`pdftoppm`/`pdftocairo` из уже бандленного Poppler, или MuPDF). Tesseract сейчас не бандлится (тяжёлый с traineddata) - реалистичен winget/PATH. Качество - известное ограничение (Tesseract медленный на плохих сканах, Ollama vision медленный без GPU).

**[23] Комикс-архивы CBZ/CBR/CB7/CBT как HTML-галерея** _(Средний / Средние)_
CBZ - это ZIP (код извлечения уже есть); CBR/CB7/CBT - RAR/7z (shell-out к 7-Zip). Сортировка картинок по имени, по HTML-странице на изображение + thumbnail-TOC через существующий navbar/zoom. С OCR можно распознавать текст в баблах.
- Видели: Calibre, MuPDF, Okular, Sumatra, YACReader.
- Проверка (high): ветка image-only HTML уже есть в `internal/pdf/extract.go`. Замечание: YACReader/Sumatra/Okular HTML-экспорта НЕ имеют (только вьюверы) - feature валиден за счёт Calibre/MuPDF.

**[24] Поддержка DjVu на вход** _(Средний / Средние)_
По образцу MOBI (shell-out к Calibre) - shell-out к DjVuLibre: `djvutxt` тянет скрытый OCR-слой в `<p>`, `ddjvu` рендерит страницы. Детект на PATH с сообщением "установите DjVuLibre".
- Видели: DjVuLibre, Calibre (DJVU Input), Sumatra (вьювер).
- Проверка (high): подтверждено man-страницами; Windows-бинарники есть (`djvutxt.exe`, `ddjvu.exe`, релиз 2025-07-14). Многие DjVu уже несут OCR-слой -> читаемый HTML без затрат на OCR.

**[35] Перевод субтитров SRT/VTT в билингва-HTML** _(Низкий / Средние)_
Парсить cue в (индекс, таймкод, текст), гнать через перевод, рендерить HTML со стэкнутыми оригиналом и переводом; опционально писать обратно `.srt`.
- Видели: Immersive Translate, Ebook Translator, DocuTranslate, O.Translator. _(Не верифицировалось отдельно.)_

### 3.3 Перевод

**[5] Билингва (side-by-side) с переключателем языка** _(Высокий / Средние)_
Сейчас перевод деструктивен (`htmlproc.ReplaceTexts` перезаписывает узел, оригинал теряется). Флаг `-bilingual append|block`: вместо перезаписи вставлять сиблинг с переводом (APPEND - инлайн после оригинала, BLOCK - приглушённый абзац c классом `.dht-translation`). В navbar - переключатель "Оригинал | Оба | Перевод" через body-класс.
- Видели: epub-translator (oomol-lab - точный API REPLACE/APPEND_TEXT/APPEND_BLOCK), Ebook Translator, PDFMathTranslate (dual/mono).
- Проверка (high): build-time билингва доказана в нескольких инструментах; reader-side переключатель - только в ридерах/расширениях (Immersive Translate, Koodo), но это здравый синтез двух паттернов. **Поправки**: EbookLib и Pandoc билингву НЕ делают (ложные цитаты); состояние navbar хранит в `sessionStorage`, не `localStorage`.

**[6] Постоянный дисковый кэш перевода (resume)** _(Высокий / Средние)_
`CachingClient` сейчас in-memory и умирает с процессом - прерванный Ollama-прогон перепереводит всё, платные Google-символы биллятся заново. Сериализовать `src:dst:text -> перевод` на диск (под выходной папкой или `%LOCALAPPDATA%\doc-html-translate\cache`), грузить до перевода, дописывать по батчам; `-force` чистит.
- Видели: PDFMathTranslate (сильнейший аналог - SQLite-кэш `~/.cache/pdf2zh/cache.v1.db`, ключ engine+params+text, `--ignore-cache`), Ebook Translator, tinbox (`--checkpoint-dir`).
- Проверка (high): ключи уже `fmt.Sprintf("%s:%s:%s",..)`, путь `%LOCALAPPDATA%` уже резолвится. **Оговорка**: подход "переписывать весь JSON на батч" не crash-safe и O(n); рекомендуется SQLite (`modernc.org/sqlite`, pure-Go) либо atomic write-temp-then-rename.

**[7] Подключаемые бэкенды OpenAI-совместимые / DeepL** _(Высокий / Средние)_
`translator.Client` - уже чистый интерфейс. Добавить за флагами `-openai` (OpenAI-совместимый chat/completions через `-api-base`+ключ: OpenAI, DeepSeek, Gemini-gateway, LM Studio, удалённый Ollama) и `-deepl` (DeepL free/pro REST). Каждый ~один файл + case; батчинг/retry/прогресс/кэш оборачивают любой.
- Видели: Ebook Translator (Google/OpenAI/Gemini/DeepL + кастомные), epub-translator (OpenAI/DeepSeek), tinbox (litellm), DeepL REST.
- Проверка (high): DeepL - простой JSON-over-HTTP, форма как у `GoogleClient`, реально ~один файл. **Оговорка**: OpenAI-совместимый возвращает прозу, не выровненный массив - надо переиспользовать `parseNumberedResponse`+echo-back retry из `ollama.go` (наследует ту же хрупкость), так что половина "OpenAI" не совсем "один файл".

**[8] Пользовательский глоссарий (CSV)** _(Высокий / Средние)_
Флаг `-glossary path.csv` (source,target). Для Ollama - инжектить термины в секцию Rules промпта ("всегда переводи X как Y"); для Google - подмена защищённых терминов плейсхолдерами до отправки и восстановление после.
- Видели: DeepL (CSV/TSV glossary), BabelDOC (`--glossary-files`, инжект в промпт - точный аналог), Translation Agent (Ng).
- Проверка (high): в `ollama.go` уже есть секция "Rules" (строки 276-290), `encoding/csv` - stdlib. **Оговорки**: плейсхолдер-подмена ломает грамматическое согласование для флективных языков (рус/укр) - DeepL этого избегает грамматической адаптацией; Ollama-инжект best-effort, не гарантирован.

**[29] Опциональный LLM-пасс склейки абзацев и чистки артефактов** _(Средний / Средние)_
Опциональный пасс после извлечения: слать черновой текст в уже подключённый Ollama для склейки разорванных переносом страниц абзацев, де-дефиса, удаления OCR/лигатурного мусора (код уже детектит лигатуры в `isLigaturesArtifact`). До перевода и генерации TOC-сниппетов.
- Видели: LlamaParse (сильнейший - "document-level" режимы против разрыва абзацев на границе страниц), Marker (`--use_llm`, Ollama-backed). Mathpix - НЕ имеет такого пасса (цитата неверна).
- Проверка (high): `internal/translator/ollama.go` - готовая инфраструктура. **Оговорка**: малые локальные модели (`gemma3:12b`) могут галлюцинировать при свободной "чистке" - делать opt-in, строгий промпт, валидировать против оригинала.

**[30] Reflection/самокритика качества LLM-перевода** _(Средний / Средние)_
Флаг `-reflect`: после первого перевода страницы слать (source, draft) обратно модели для критики и улучшения (петля Ng translate -> reflect -> improve). Обёртка-`Client`, только для LLM-бэкендов (Google v2 пропускать).
- Видели: Translation Agent (Andrew Ng, MIT, июнь 2024 - эталонная реализация).
- Проверка (high): паттерн обёртки уже используется (`CachingClient`); `ReflectClient` встаёт идентично. **Поправки**: OpenAI/Anthropic-клиента в репо НЕТ (grep пуст) - сегодня применимо ровно к Ollama; "удваивает стоимость" оптимистично - честный reflect+improve это ~3x (два доп. вызова), если не слить reflect и improve в один.

### 3.4 Чтение (UX) - инъектируется в выходной HTML через `navbar.go`

**[9] Полнотекстовый поиск по всей книге** _(Высокий / Средние)_

Виджет в navbar: список страниц со сниппетами, переход + подсветка. Полностью офлайн; для `file://` (где `fetch` заблокирован) - инлайн `<script>`-блоб. Строится после перевода -> ищет и по переводу.

**[12] Встроенные темы чтения** _(Высокий / Низкие)_
CSS-переменные под body-классом + тумблер в navbar (Light/Sepia/Dark/Night), выбор в `localStorage`. Темы поверх CSS книги без пересборки.
- Видели: Thorium (Neutral/Sepia/Night), Foliate (9+ тем), Calibre viewer.
- Проверка (high): код уже инжектит `<style id="dht-nav">` и JS в каждый файл. **Важная фактическая поправка**: зум-синк использует `sessionStorage` (не `localStorage`), а он НЕ переживает закрытие сессии - для темы нужен именно `localStorage`, т.е. это НЕ "тот же механизм, что зум". Применять тему на каждой загрузке страницы (каждая глава - отдельный файл).

**[13] Всплывающий словарь/Wikipedia/перевод по выделению** _(Высокий / Низкие)_
JS-виджет: по выделению/двойному клику - попап "Определение / Wikipedia / Перевести выделение", открывает публичные эндпоинты (Wiktionary/Wikipedia/Google Translate URL) в новой вкладке с подставленным текстом и языками книги.
- Видели: Foliate (Dictionary/Wikipedia/Translate с v1.4.0), Calibre viewer (URL-шаблоны с `{word}` - точнейший аналог), KOReader, Koodo.
- Проверка (high): URL-схемы подтверждены (`translate.google.com/?sl=&tl=&text=&op=translate`). **Оговорки**: ридеры делают in-app lookup (часто офлайн-словари) - предложенный вариант самый низкофидельный и онлайн-зависимый при "офлайновом" выводе; URL Google Translate недокументирован/нестабилен; язык книги из EPUB часто отсутствует (нужен фолбэк `tl=auto`); приватность - каждый lookup шлёт выделение в Google/Wikimedia, нужен тумблер/согласие, не on-by-default.

**[14] Сохранение позиции чтения + индикатор прогресса** _(Высокий / Низкие)_
Расширить `dht-zoom-sync`: писать `{spineIndex, scrollFraction}` в `localStorage` по стабильному ключу книги; на `index.html` - ссылка "Продолжить чтение", в navbar - тонкий индикатор прогресса.
- Видели: Foliate, Kavita ("Continue From" - почти точный дизайн), Thorium, Koodo, Readest.
- Проверка (high): код уже эмитит `Current/Total` и инжектит inline-скрипт. **Оговорки**: ключ должен включать стабильный book-id/хэш-заголовка (а не просто папку - `file://` origin'ы коллизятся); процент только по гранулярности spine-индекса (приблизительный); смещение хранить как долю `scrollHeight`, не пиксели (ломается при зуме). Серверные из списка (Komga/Kavita/Ubooquity/Stump) хранят прогресс в БД, не в localStorage.

**[15] Панель типографики** _(Высокий / Средние)_
Попап "Aa": семейство шрифта (несколько web-safe + dyslexia-friendly), кегль, интерлиньяж, ширина/поля, выключка, CSS-переносы. Через CSS-переменные на `:root`, `localStorage`. Обобщает существующий Ctrl+wheel зум.
- Видели: Foliate (font/spacing/margins/justify/auto-hyphenation), Thorium ("Readable (Dyslexia)" шрифт), Calibre viewer (OpenDyslexic).
- Проверка (high): код уже применяет настройку к `document.documentElement.style`. **Оговорка**: `hyphens:auto` зависит от языка (нужен правильный `lang` + словарь переносов браузера); сейчас `index.html` всегда `lang="en"` (htmlgen.go:80) - не-английские книги будут перенесены неверно. Для hyphenate цитировать Foliate, не Thorium (у Thorium не подтверждено).

**[16] Чтение вслух (TTS) с подсветкой предложения** _(Высокий / Средние)_
Контроллер на нативном Web Speech API (`window.speechSynthesis`) - без бэкенда и сети. Play/pause/stop в navbar читают видимый текст и подсвечивают текущее предложение (оборачивать предложения в span на генерации). Голос/язык по умолчанию - целевой язык книги; авто-переход на следующую страницу через существующую edge-навигацию.
- Видели: Thorium (подсветка предложения/слова, явно Web Speech API), Calibre viewer, Readest (выбор языка для переведённых книг).
- Проверка (high): паттерн инъекции тот же. Надёжно в Chromium (Edge/WebView2/Chrome), зависит от установленных в ОС голосов (та же зависимость, что у Thorium), работает на `file://`.

**[17] Выделения, закладки, заметки + экспорт/импорт JSON** _(Средний / Средние)_
JS: выделение -> цветной хайлайт/закладка/заметка прямо в статичном HTML. Аннотации - JSON-объект на книгу в `localStorage`, панель "Мои закладки" на `index.html`. Якорение по text-quote (exact + prefix/suffix). Экспорт -> JSON + Markdown; импорт.
- Видели: Foliate (JSON на книгу), Calibre viewer (экспорт в Markdown), KOReader (text/md/html/json), Thorium, Koodo.
- Проверка (high): логика 100% клиентская. **Поправка**: Foliate якорит через EPUB CFI, а НЕ text-quote (W3C/Hypothesis - другой проект); text-quote для статичного HTML лучше, но цитата-по-авторитету неверна. `localStorage` под `file://` чистится браузером - JSON-sidecar экспорт это реальный механизм надёжности, не приятная мелочь; аннотационный JS должен грузиться на каждой главе.

**[27] Сноски/примечания с всплывающим предпросмотром** _(Средний / Средние)_
Детектить маркеры/определения сносок (EPUB `epub:type=noteref/footnote`, FB2 `<note>` - сейчас выбрасываются), переписывать в доступный HTML: надстрочный якорь + обратная ссылка + JS-попап вместо ухода со страницы.
- Видели: Foliate (popup footnotes - но это ридер, read-time), Pandoc/mammoth (только статичный anchor+back-link, БЕЗ попапа).
- Проверка (подтв. **с поправкой**): ни один инструмент не делает полный пайплайн (извлечь -> статичный HTML -> JS-попапы) - это синтез "Pandoc-style структура + Foliate-style попап-слой". Премиса "Word notes через office path" ложна (office-кода нет). FB2-drop подтверждён.

**[32] Постраничный режим vs скролл** _(Низкий / Средние)_
Тумблер в navbar между скроллом и CSS-columns постраничным видом (перелистывание на prev/next-клавиши). _(Не верифицировалось отдельно.)_ Видели: Foliate, KOReader, Readest, Calibre viewer, Thorium.

### 3.5 Вывод и библиотека

**[10] Страница-библиотека по всем книгам** _(Высокий / Средние)_
Режим `-library D:\out` сканирует родительскую папку на подпапки книг (у каждой есть `index.html`), читает заголовок и обложку, пишет `library.html` - сетку обложек со ссылками внутрь. Кнопка "Открыть библиотеку" в GUI. Пара к watch-folder режиму (авто-конвертация брошенных файлов).
- Видели: COPS (HTML-каталог), calibre2opds/calibre-htmlshelf (статичный self-contained `index.html` с обложками - ближайший аналог), Komga/Kavita/Calibre-Web (динамические).
- Проверка (high): `os.ReadDir` + чтение `<title>` из `index.html`. **Оговорки**: "чистая агрегация" преувеличена - `opfMetadata` не хранит структурного поля обложки, путь надо ре-деривить из OPF/manifest; для TXT/MD/PDF обложек часто нет - сетка деградирует в плейсхолдеры для заметной доли смешанной библиотеки.

**[11] Экспорт в один самодостаточный HTML-файл** _(Высокий / Средние)_
Флаг `-single`: после извлечения+TOC+перевода склеить книгу в ОДИН `.html` - конкатенация тел spine под TOC (внутри-документные якоря вместо меж-файловых ссылок), base64-инлайн `<img>` как data-URI, инлайн CSS в `<style>`, инлайн/фолбэк шрифтов. Переиспользует уже строящиеся `x/net/html` деревья.
- Видели: Pandoc (`--embed-resources` - точнейший аналог), pdf2htmlEX (всё inline по умолчанию), monolith, SingleFile.
- Проверка (high): пайплайн уже делает ~80%. **Поправки**: Calibre HTMLZ - это ZIP с папкой `images/`, НЕ единый embedded HTML (цитата ложна); Docling не подтверждён. **Риски**: большие книги -> очень большой data-URI HTML (pdf2htmlEX сам предупреждает про >20 страниц) - нужен per-book size-warning/opt-in; коллизии `id`/якорей при конкатенации (namespace'ить); `@font-face url()` в CSS надо тоже переписывать в data-URI (это парсинг CSS, не только HTML).

**[18] Полные метаданные + обложка-"джекет"** _(Средний / Низкие)_
Расширить `opfMetadata` (сейчас только `<title>`): автор, язык, издатель, дата, ISBN, описание, темы; аналоги из PDF `/Info`, FB2 `<title-info>` (авторы парсятся, но выбрасываются), MOBI/EXTH. Извлекать обложку (EPUB; рендер 1-й страницы PDF). Блок-джекет наверху `index.html`, sidecar `metadata.json`, `<html lang>` из языка -> авто-`-src`.
- Видели: Calibre `ebook-meta`, Komga, Kavita, EbookLib, Sigil.
- Проверка (high): `golang.org/x/image` уже зависимость; Poppler `pdftoppm` уже бандлится (рендер обложки PDF); FB2-авторы уже парсятся. **Оговорки**: выгода от `<html lang>` для авто-перевода преувеличена (Chromium детектит язык статистически по n-граммам, может игнорить `lang`) - надёжный выигрыш в авто-заполнении своего `-src`; PDF `/Info` часто пуст, 1-я страница != обложка.

**[22] Обратный экспорт в EPUB / DOCX** _(Средний / Высокие)_
Флаг `-export epub|docx`: упаковать переведённый spine-HTML обратно в валидный EPUB3 (OPF из `epub.Book`, `nav.xhtml` из TOC, zip с правильным mimetype) либо DOCX.
- Видели: Pandoc (`-f html -t epub3/docx`), Calibre, Ebook Translator.
- Проверка (high): **EPUB3 - на чистом stdlib** (`archive/zip`+`encoding/xml` уже на чтение OPF, писать - инверсия). **Поправка**: `epub.Book` - только метаданные, контент на диске - писатель читает HTML с диска, не из памяти. **DOCX - слабая половина**: нет stdlib-писателя, Go-OOXML библиотеки ограничены/AGPL; фидельность HTML->DOCX тяжёлая. Рекомендация: EPUB3 первым (низкий риск), DOCX - отдельный дорогой пункт.

**[28] Экспорт в Markdown / JSON** _(Средний / Средние)_
Флаг output-формата: писать книгу как чистый Markdown или структурный JSON (заголовки, абзацы, картинки) для note-app/SSG/RAG-пайплайнов.
- Видели: Marker (PDF->md+JSON), Docling, MarkItDown (только md), Pandoc (`-t json` native AST).
- Проверка (подтв. **с поправкой**): несущая премиса "тонкий сериализатор над `epub.Book`" ЛОЖНА - `epub.Book` хранит только Title/Manifest/Spine/BasePath, БЕЗ заголовков/абзацев/картинок; контент - HTML-файлы на диске, `ExtractTexts` даёт плоские сегменты без уровней. Реально: новый пасс, обходящий DOM каждого spine-документа (h1-h6 -> headings, p -> paragraphs, img -> refs). Умеренные трудозатраты, не тривиально; "page numbers" - чужеродно для reflowable EPUB.

### 3.6 Приватность и quality-of-life

**[19] Валидация вывода + отчёт** _(Средний / Низкие)_
После генерации - лёгкий пасс: парсится ли каждая страница, резолвится ли каждая внутри-книжная ссылка и `src`, совпадает ли spine с тем, что записано, существуют ли цели TOC. Отчёт в GUI-лог и опционально `results.html`.
- Видели: Calibre ("Check book" - точнейший аналог: битые ссылки/несвязанные ресурсы/целостность spine), Sigil (F7 Well-Formed + FlightCrew).
- Проверка (high): `x/net/html` уже парсит каждую страницу; `normalizeXHTMLToHTML` уже резолвит пути. **Риск**: текущий rewrite через `strings.ReplaceAll(content,".xhtml",".html")` - именно тот хрупкий паттерн, что плодит битые ссылки; валидация должна пропускать `http(s)://`, `mailto:`, fragment-only (`#id`).

**[20] Пакетная конвертация папки/маски** _(Средний / Низкие)_
Принимать директорию/glob/несколько файлов, конвертить каждый поддерживаемый за один прогон (переиспользуя идемпотентный пайплайн и `-noopen`), каждый в свою подпапку, сводка успехов/пропусков, опционально `library.html`.
- Видели: DeepL CLI (точнейший - dir+glob+`--pattern`+`--concurrency`), Ebook Translator (Batch Mode).
- Проверка (high): пайплайн уже идемпотентен со skip-if-`index.html`. **Поправки**: Calibre `ebook-convert` строго single-input (batch только через внешний for-loop); tinbox batch НЕ имеет. **Оговорки**: `config.ParseArgs`/`doc-html-ui` берут один позиционный `InputFile`; `translateContent` делает блокирующий `fmt.Scanln()` на ошибке перевода - нужен неинтерактивный путь для unattended-батча.

**[21] Оценка стоимости + жёсткий лимит USD** _(Средний / Низкие)_
Превратить нынешний advisory-диалог Google в enforce-гард: флаг `-max-cost N` прерывает до отправки, если оценка превышает N; running-tally останавливает посреди книги по достижении лимита и пишет частичный-но-возобновляемый результат (пара к [6]).
- Видели: tinbox (`--max-cost` USD + `--dry-run` + checkpoint - почти точная реализация), DeepL (серверный месячный cap, не CLI-флаг).
- Проверка (high): код уже считает `estCost = chars/1e6*20` и показывает advisory-диалог. **Поправки**: mid-stream-halt у tinbox недокументирован (pre-flight-guard подтверждён); BabelDOC - token-quota, не USD-cap (неверная цитата); O.Translator не подтверждён. Реально: обобщить `*20` в пер-движковую `CostModel`, pre-flight abort (тривиально), budget-tracking decorator для mid-stream, возобновляемость через кэш [6].

**[33] Авто-alt-текст / подписи к картинкам (локально)** _(Низкий / Средние)_
Переиспользовать Ollama, но звать локальную vision-модель (llava/gemma vision) на извлечённых картинках -> `alt` и `<figcaption>`. Полностью офлайн, переводимые подписи. _(Не верифицировалось отдельно.)_ Видели: MarkItDown, Adobe, Marker, MinerU.

## 4. Дополнительно найдено критиком полноты (за пределами 36 фич)

Категории конкурентов, которые **не исследовались** в основном проходе: AI-Q&A/RAG "чат с документом"; проверка/ремедиация доступности (WCAG/EPUB-A11y); in-image OCR-перевод комиксов с инпейнтингом; генераторы аудиокниг (TTS-в-файл); экосистема языкового обучения (sentence-mining/Anki); доставка на устройства и OPDS-серверы; ML-layout/document-VLM бэкенды извлечения.

Конкретные пропущенные фичи (каждая подтверждена названными инструментами):

1. **Чат-с-книгой / RAG-Q&A и AI-резюме глав (локально через Ollama)** - роадмап использует LLM только для перевода и чистки, но огромная категория конкурентов - задавать вопросы книге и получать резюме. Продукт уже бандлит Ollama -> офлайн-RAG-индекс по HTML это естественная приватная фича. Видели: LocalRAG (нативный EPUB + резюме глав), AnythingLLM/Jan/LM Studio, Koodo (AI summaries).
2. **Доступность: WCAG/EPUB-A11y вывод + Ace-style отчёт** - "валидация вывода" [19] проверяет только ссылки. Целый стандарт (EPUB Accessibility 1.1 / WCAG 2.1 AA), с 2025 enforce'ится European Accessibility Act, требует корректной иерархии заголовков, порядка чтения, landmark-ролей, alt-текста, контраста. Юридически релевантно для распространения в ЕС. Видели: DAISY Ace, PubCoder.
3. **In-image / panel OCR-перевод комиксов с удалением текста (inpainting) и ре-леттерингом** - [23] CBZ это пассивная галерея, [4] OCR для PDF, но они не комбинируются: перевод текста, впечатанного В картинку (бабблы манги, подписи диаграмм). Видели: comic-translate, manga-image-translator, Immersive Translate.
4. **Экспорт аудиокниги (TTS-в-файл: MP3/M4B с главами)** - [16] это эфемерное чтение в браузере, а не рендеренный аудио-файл. Продукт уже сегментирует главы. Пара к переводу (переведённые аудиокниги). Видели: ebook2audiobook, epub_to_audiobook (Kokoro), Murf.
5. **Цитаты/библиография/перекрёстные ссылки (CSL, in-text refs)** - [27] покрывает сноски, но не библиографические ссылки и не разрешение внутренних перекрёстных ссылок (нумерация рисунков/таблиц/формул). Для академических PDF/EPUB - значимый пробел. Видели: Pandoc.
6. **RTL (арабский/иврит) и CJK вертикальное письмо + ruby/furigana** - роадмап не трогает направление письма. Корректные `dir=rtl`/bidi, `writing-mode`, ruby-аннотации - известно сложные, высокая ценность для учащихся (а продукт позиционируется на перевод/обучение).
7. **Тулкит языкового обучения: трекинг известных слов, частотная подсветка, экспорт в Anki (sentence mining)** - [13] lookup-попап на этом останавливается. Билингва+перевод прямо целят в учащихся. Видели: Migaku, LingQ.
8. **Send-to-device / Send-to-Kindle (email/USB) и OPDS-каталог** - [22]/[10] покрывают экспорт и страницу-библиотеку, но не доставку: emailing EPUB на Kindle или OPDS-фид для телефона/e-ink (KOReader, Koodo).
9. **Кросс-девайс синхронизация прогресса/выделений (напр. KOReader-совместимая)** - [14]/[17] хранят локально и предполагают одну машину. Все современные ридеры (Readest, Koodo) синкают; Readest рекламирует KOReader-совместимый sync. JSON-sidecar'ы уже есть -> файловый/WebDAV-синк закрыл бы пробел.
10. **Layout-aware извлечение через document-VLM / ML-модель (Docling/Marker)** - [25]/[26]/[4]/[34] перечислены раздельно, но state-of-the-art - единая ML-модель (Docling GraniteDocling VLM, Marker Surya), совместно восстанавливающая порядок чтения, таблицы, формы, формулы. Локально через Ollama vision - стратегическое направление.
11. **Авто-детект языка + по-сегментный детект до перевода** - фичи перевода предполагают известный source. Конкуренты авто-детектят язык (и пропускают сегменты, уже на целевом языке - экономия API и качество). Пара к cost-cap [21]. Видели: Immersive Translate.

**Вердикт критика по наивысшему leverage** (учитывая активы продукта - бандленный Ollama, сегментация глав, JSON-sidecar'ы, MSIX-десктоп): (1) офлайн-RAG-чат + AI-резюме (переиспользует Ollama, крупнейшая полностью пропущенная категория); (2) WCAG-совместимый вывод + Ace-style отчёт (юридически релевантно EU EAA, согласуется с pure-HTML выводом); (3) экспорт аудиокниги M4B/MP3 (переиспользует структуру глав, комплементарно переводу); (4) RTL/CJK + ruby + слой языкового обучения/Anki (прямо обслуживает аудиторию перевода/учащихся). Остальное (CSL, in-image комиксы, OPDS-доставка, кросс-синк, VLM-бэкенд, авто-детект языка) - реальные фичи конкурентов, но ниже по уникальности или тяжелее.

## 5. Рекомендованный порядок внедрения

Синтез приоритета, трудозатрат и "переиспользует то, что уже есть".

**Волна 1 - быстрые победы высокого приоритета, низкие трудозатраты, чистый клиентский JS в `navbar.go`:**
[12] темы, [13] lookup-попап, [14] позиция чтения, плюс из QoL [19] валидация, [20] пакет, [21] cost-cap. Минимум кода на Go, максимум видимой пользы.

**Волна 2 - ядро ценности конвертации/перевода (высокий приоритет, средние трудозатраты):**
[1] настоящий TOC, [2] нормализация текста, [5] билингва, [6] дисковый кэш перевода, [7] DeepL/OpenAI-бэкенды, [8] глоссарий, [9] полнотекстовый поиск, [15] типографика, [16] TTS, [10] библиотека, [11] single-file HTML.

**Волна 3 - расширение охвата форматов и фидельности (высокий/средний):**
[3] DOCX/Office (большая доля отклоняемого контента), [4] OCR (крупнейшая отказная категория), [18] метаданные/обложка, [17] аннотации, [23] CBZ, [24] DjVu, [22] EPUB-экспорт (только EPUB, DOCX отложить).

**Волна 4 - стратегические направления из критики (новые категории):**
RAG-чат + AI-резюме (переиспользует Ollama), WCAG-доступный вывод + Ace-отчёт, экспорт аудиокниги M4B. Затем тяжёлое/нишевое: [25]/[26] (с ML-оговорками), [34] математика, RTL/CJK/ruby, языковое обучение/Anki, OPDS-доставка, кросс-синк.

**Сквозные технические заметки из верификации (важны до старта):**
- Унифицировать клиентское хранилище: зум использует `sessionStorage`, но темы/позиция/типографика требуют `localStorage` (переживает сессию). Документировать или мигрировать.
- `<html lang>` зашит как `"en"` (htmlgen.go:80) - чинить до фич, зависящих от языка (переносы, авто-`-src`, голос TTS).
- Многие "переиспользует существующее" премисы частично неточны (`extractImages` даёт XObject'ы, не растры страниц; `epub.Book` - только метаданные; `xml.Unmarshal` теряет порядок инлайна) - закладывать реальный объём, а не "тонкий сериализатор".
- Лоссовые эвристики ([2], [25], [26]) делать off-by-default с тумблерами (модель Calibre), чтобы не регрессировать корректные книги.

## Приложение B. Методология и провенанс

- **Параллельный sweep:** 6 категорий-агентов, каждый слепой к остальным, обязаны подтверждать фичи фетчем первоисточника, а не выдумывать. -> 69 кандидатов.
- **Синтез:** дедупликация/группировка/приоритизация в 36 фич.
- **Адверсариальная верификация:** 31 высоко/средне-приоритетная фича проверена отдельным скептиком, инструктированным опровергать (искать первоисточник + оценивать реализуемость в Go). Результат: 100% подтверждены как реальные у названных конкурентов и реализуемые; многие с конкретными скептическими поправками (раздутые списки цитат подрезаны, ложные премисы помечены) - они включены в заметки выше.
- **Критик полноты:** отдельный проход на пропущенные категории/инструменты/фичи -> +11 фич, +7 категорий.
- Метрики прогона: 45 агентов, ~1.93M токенов, 598 веб-вызовов, длительность ~17.5 мин.
